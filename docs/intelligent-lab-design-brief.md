## 现有业务基础

以当前代码及 Prisma 模型为准：

- 样本：组织、cDNA、全血、血浆、细胞；项目、批次、冻存管 ID、短码和储存信息。
- 实验：富集、阵列、连接、建库、测序、单细胞、组织切片、贴片、制取 cDNA。
- 取样登记连接来源样本与派生样本；支持上游、下游追溯。
- 实验结果支持暂存、提交；已有体积、浓度、片段、策略、吸光度、单细胞计数与活率等字段。
- 测序结果已有下机数据量、上传路径、测序策略等字段。
- 当前表单配置只能调整已预留字段；实验限制配置约束样本可参与的实验，不是完整流程编排器。

当前尚无独立的分析运行、结构化质控判定、参数方案版本、设备任务与事件模型。多实验对比也需要新增查询与展示能力。

## 总体界面

| 工作区 | 核心任务 | 第一阶段安排 |
| --- | --- | --- |
| 样本 | 入库、查找、完整链路、关联实验、加入对比 | 重做现有能力 |
| 实验 | 取样登记、任务列表、参数填写、暂存与提交 | 重做现有能力 |
| 对比与优化 | 选择实验、设置基准、查看参数与结果差异、保存对比 | 新增核心工作区 |
| 项目 | 汇总项目样本、批次与实验 | 承接现有项目查询 |
| 质控与分析 | 规则判定、分析运行、结果证据与版本 | 分阶段新增 |
| 运行监控 | 人工/设备任务进度、事件、告警与执行回执 | 先设计数据接口，设备接入后启用 |

实验室配置从设置入口进入，逐步管理样本类型、字段与单位、实验模板、质控规则和权限。未来的实验室切换需要真实的数据隔离设计。

## 联合对比的主要交互

1. 从样本链路或实验列表勾选记录并“加入对比”；允许同一样本的重复实验和多个样本之间的实验对比。
2. 明确选择同阶段对比或跨阶段追溯。不同阶段的同名字段不能默认作为同一指标。
3. 设置一条基准记录；记录作为列，样本背景、输入参数、执行条件、结果和质控作为分组行。
4. 显示值、单位、相对基准的差异；支持只看差异与展开原始证据。大批量记录提供筛选和汇总，不能只靠无限扩展表格。
5. 先展示可比性：样本来源、起始质量、方法/方案版本、试剂批次、设备及执行者、缺失数据。缺失和不适用不计为零。
6. 结果图与参数图分开呈现。明确优化目标，例如特定质量指标、产出或一致性，并同时展示约束，不能默认“浓度越高越好”。
7. AI 建议展示依据、适用范围、数据不足与候选变更。创建下一轮方案草稿，由实验结果验证效果。
8. 保存对比集合时固定记录版本、基准、指标和纳入/排除条件，以便复现。

跨样本的差异可能同时来自样本背景和执行条件。界面需要区分“观察到的关联”“待验证假设”和“经后续实验验证的效果”，不能把单次结果更高直接解释成参数改进的因果效果。

## 从现在开始保留的数据

以下为逻辑对象，具体表结构在实施时确定。

| 对象 | 必要信息 | 用途 |
| --- | --- | --- |
| 实验运行 | 稳定 ID、实验类型、来源/输出样本、关联项目、模板版本、执行状态 | 人工与设备共用任务对象 |
| 参数方案 | 参数定义、数值、单位、版本、父版本、变更原因、确认者 | 区分建议、批准与实际执行 |
| 执行记录 | 实际参数、人工/设备来源、执行者或设备、发生与接收时间、偏差原因 | 还原真实过程 |
| 测量与质控 | 指标、数值、单位、测量方法、原始文件、规则版本、判定与复核 | 让结果可比较、可追溯 |
| 分析运行 | 输入记录版本、分析方法/软件版本、输出文件、状态、时间 | 参数与分析结果关联 |
| 优化迭代 | 目标、约束、对比集合、建议版本、确认动作、验证运行、评价结果 | 闭合优化循环 |
| 设备任务与事件 | 设备/外部任务 ID、命令版本、回执、事件序号、状态与异常 | 接入设备后追踪执行 |

原始记录保留；修订通过新版本关联旧版本，记录理由与来源。参数优化改变下一轮实验计划，不能覆盖历史实际参数。

### 与现有模型直接相关的注意点

- `inputAmount` 在不同实验中可能表示 ng 或 µL，需要按实验类型与版本定义语义，不能仅按字段名联合分析。
- `libraryDuration`、片段相关字段及 `dataAmount` 存在文本类型；历史数据迁移应保留原文与解析状态，无法可靠解析的值不强制转换。
- 通用建库与单细胞使用不同的文库浓度字段，需建立指标映射并保留原字段来源。
- 当前提交时间和更新时间不能替代完整的执行事件、测量时间与修订日志。
- 测序下机结果关联登记单；如果一次登记包含多个文库，登记总数据量不能直接归为每个样本的数据量，逐样本指标需要明确归属。
- 历史记录中没有的协议版本、试剂批次或设备信息应标为“未记录”，不能补造。

## 演进顺序

1. **人工记录与联合对比**：完成视觉改造、现有流程迁移、记录对比、单位语义和版本/来源基础。首个对比实验类型待用户确定。
2. **辅助优化**：结构化质控与分析，定义目标与约束，生成候选方案、人工确认、验证与效果回看。算法有效性通过真实验证评价。
3. **设备协同**：先接入结果文件和只读事件，再接任务下发及回执；记录计划与实际值，处理重复事件、连接中断、失败和重试。
4. **限定范围内的自主调控**：在已验证流程、明确参数边界与设备能力内执行闭环；界面保留运行状态、异常处置、暂停和人工接管入口。

前两阶段界面以人类执行为主，不展示虚假的在线设备或实时控制能力。执行进度不能仅由“结果已填写”推断，结果也不能仅由“命令已发送”推断。
